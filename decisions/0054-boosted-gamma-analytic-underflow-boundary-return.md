# ADR-0054: Rejection samplers with an analytically-provable underflow/overflow boundary return that boundary value instead of throwing

**Date**: 2026-08-11
**Status**: Accepted

## Context

[ADR-0049](0049-continued-fraction-convergence-throw.md) established that an iterative numerical primitive without a bounded-error guarantee — including the generic rejection sampler in `src/algorithms/rejection.js` — throws `Error` when it exhausts its iteration budget, because "a rejection sampler that exhausts its trial budget has produced no sample at all... so silently returning something would have to be a fabricated value."

`src/dist/_gamma.js`'s `boostedGamma(r, a, b)` samples `Gamma(a, b)` for `a < 1` via the boost identity `X · U^(1/a)` (`X ~ Gamma(a+1, b)`, `U ~ Uniform(0,1)`), guarded by a `while (result === 0)` rejection loop (added for #1379) that redraws whenever the boost factor underflows to exact `0.0`. For shape `a` below a precisely derivable threshold `a* ≈ 3.13×10⁻¹³` — derived from the xoshiro128+ PRNG's 32-bit output resolution and `Number.MIN_VALUE`'s underflow boundary: `a* = ln(u_max) / ln(Number.MIN_VALUE)` where `u_max = 1 - 2⁻³²` is the largest value the PRNG can produce below 1 — **every one of the PRNG's `2^32` possible outputs** underflows the boost factor to exactly `0.0`. Below `a*`, the rejection loop has provably zero acceptance probability and never terminates (#1384).

This is a different situation from the continued-fraction and generic-rejection-sampler cases ADR-0049 covers. There, an exhausted budget leaves the last iterate "arbitrarily far from the true value, with no way for the caller to tell" — the loop simply ran out of budget before converging, but more iterations (or a larger budget) would eventually have produced a materially different, better answer. Here, for `a < a*`, no additional iterations would ever change the outcome: the true `Gamma(a, b)` variate is, for every possible draw the PRNG can produce, provably smaller in magnitude than `Number.MIN_VALUE`, the smallest positive value float64 can represent. The correctly-rounded IEEE-754 double-precision representation of that true value genuinely *is* `0.0` — not a truncated partial computation, but the exact answer the type system is capable of expressing. Per [ADR-0015](0015-return-value-and-error-conventions.md)'s fourth channel, "the mathematically correct value happens to be zero" is not an error condition.

The same reasoning applies in the opposite direction to `InverseGamma`, `BetaPrime`, and `StudentT`, which compose `boostedGamma`'s output via reciprocal or ratio transforms (`1/x`, `x/y`) guarded by their own `while (!Number.isFinite(...))` rejection loops (also added for #1379): once the underlying gamma draw is provably `0.0`, the reciprocal or ratio provably overflows on every possible draw. The correctly-*rounded* boundary here is `Infinity`, not `Number.MAX_VALUE`: IEEE-754 rounds a value to `Number.MAX_VALUE` only in the razor-thin band immediately above it (up to roughly `MAX_VALUE + (MAX_VALUE − nextDown(MAX_VALUE))/2`), and rounds to `Infinity` for anything beyond that band. The true reciprocal/ratio here is not merely somewhat beyond `Number.MAX_VALUE` — for `InverseGamma`'s `1 / 0`, `BetaPrime`'s `x / 0`, and `StudentT`'s ratio, it is unboundedly larger — so `Infinity` is both the IEEE-754-correct rounding and matches [ADR-0015](0015-return-value-and-error-conventions.md)'s third channel, "a valid query, but the answer diverges." (`Number.MAX_VALUE` was the original choice in this ADR's first draft and is a documented mistake, corrected during `/review` before the underlying PR shipped — see the CHANGELOG entry for #1384.)

`BetaPrime` and `Beta` (`src/dist/_beta.js`) each compose **two** independent gamma draws (`x / y` and `x / (x + y)` respectively), so unlike the single-sided compositions above, both operands can independently underflow when *both* shape parameters are below the threshold — producing `0 / 0 = NaN` on every attempt, not a provable overflow in a single fixed direction. No amount of resampling resolves a deterministic `NaN`. The correct boundary here is not `NaN`, `0`, or `Infinity` unconditionally, but whichever of `0`/`Infinity` (`BetaPrime`) or `0`/`1` (`Beta`) the *smaller* of the two shape parameters' draw is pulled toward: the small-shape tail asymptotic `-a·ln(Y) → Exp(1)` as `a → 0` (the same fact underlying the threshold derivation above) gives `ln(x/y) ≈ E_y/b − E_x/a` for `X ~ Gamma(a)`, `Y ~ Gamma(b)`, so the shape parameter with the larger `1/shape` term dominates the race to vanish and pulls the ratio toward the *opposite* boundary — `a < b` pulls `x` toward `0` faster (ratio `→ 0`), `a > b` pulls `y` toward `0` faster (ratio `→ ∞`/`1`), and `a === b` is a symmetric coin flip, resolved with a single extra PRNG draw rather than deterministically favoring either side.

## Decision

A rejection-sampling loop composed from `_gamma.js`'s boost identity (`boostedGamma` itself, and its downstream reciprocal/ratio consumers in `InverseGamma`, `BetaPrime`, `StudentT`, `Beta`) returns the analytically-provable **boundary value** — `0.0` for underflow, `Infinity` (sign-adjusted where relevant; `1` for `Beta`, whose range is `(0,1)` rather than `(0,∞)`) for overflow, or a shape-parameter-comparison-derived direction for the doubly-composed case (`BetaPrime`, `Beta`) — instead of throwing, when it can be established **analytically, in closed form, ahead of sampling** (not merely inferred from "the loop ran a long time") that every possible draw the PRNG's finite output space can produce leads to that same floating-point-representable boundary. This is narrower than a general license to swallow non-convergence: it applies only where the boundary condition is provable independent of which of the PRNG's `2^32` outputs actually occurs, not where a large-but-finite iteration count merely made success statistically unlikely within an arbitrary budget. For the doubly-composed distributions, the *direction* is resolved analytically before ever entering the retry loop (retrying a deterministic `NaN` cannot help), rather than as a post-exhaustion fallback.

Where the boundary is *not* analytically provable for a given input — i.e. `a >= a*`, where the boost loop has a genuine, if possibly very small, positive acceptance probability — the existing rejection loop keeps sampling per ADR-0049's default (bounded by a generous iteration cap sized against the issue's own measured worst case, not the small generic `MAX_ITER = 100` used by `rejection.js`, since the boost loop's legitimate near-boundary acceptance rate can require far more trials than a general-purpose rejection sampler's `MAX_ITER` budget assumes).

## Consequences

**Easier**: A future distribution composing `_gamma.js` (or any other sampler with a similarly provable, PRNG-resolution-derived underflow/overflow boundary) has a documented, narrow escape hatch for extreme parameter regimes that doesn't require inventing a new ad hoc sentinel value or silently hanging. The distinction from ADR-0049's default is explicit and testable: can the boundary outcome be derived in closed form from the PRNG's known output cardinality, or not?

**Harder**: This is now the second documented exception to ADR-0049's "throw on exhausted budget" default (the first being Chandrupatla's monotone-bracket guarantee). A future contributor extending this pattern to a new sampler must re-derive their own analytic proof that the boundary is unavoidable for *every* representable PRNG output — not assume by analogy that "returning a saturated constant on failure" is generally acceptable. Misapplying this exception to a case where the terminal state is only empirically likely, not analytically forced, would silently reintroduce the fabricated-value problem ADR-0049 was written to prevent.

Once `_gamma.js`/`_beta.js` started returning `0`/`1`/`Infinity` at these boundaries instead of hanging, two further consumers *downstream* of the fixed samplers broke in a new way: `BetaGeometric` and `BetaNegativeBinomial` each compose `_beta.js`'s output through an unrelated formula (`log(1-p)`, a Gamma-Poisson mixture) that neither anticipated `p` landing exactly on `0`. `BetaGeometric`'s inverse-CDF divided by `Math.log(1) = +0`, producing `-Infinity` (a sign flip from the true `+Infinity`) instead of the correctly-rounded answer; `BetaNegativeBinomial`'s mixture drove `_poisson.js`'s `lambda` to `Infinity`, which fell through that function's large-lambda loop with no return — an explicitly forbidden `undefined` per this project's return-value conventions. Both are now fixed at their own call sites (a `p === 0` guard in `BetaGeometric._generator()`; a `lambda === Infinity` guard at the top of `_poisson.js`) rather than by generalizing this ADR's rejection-loop machinery, since neither failure was a rejection loop to begin with — this is the general shape a "harder" consequence of this ADR takes in practice: fixing a sampler's own termination can newly expose a downstream consumer that was never reachable with that sampler's old (hanging) behavior, and each such consumer needs its own audit rather than a blanket fix.
